# 末秒狙击策略优化报告 —— 止盈止损与胜率

> 数据：`data\`（36 个 parquet，7,203,617 行）· 回测标的：`2026-03-11 (1).parquet`（2,018,492 笔真实成交、1,901 个市场）
> 全部价格来自**真实成交记录**，不是模型盘口 —— 你的 orderbooks 有 99.77% 的快照价差 ≥ 0.50，用它回测等于编故事。

## 一、先修正一个会误导你的指标

我第一版回测输出"胜率 72.82%"，看着像圣杯。**这个数字是错的（口径错，不是算错）**：

* `won = pnl > 0` 量的是**赚钱的交易占比**，不是**方向猜对的比例**。
* 平均入场价 0.5214 → 只要方向对就赚、方向错就亏，**盈亏平衡胜率 = 平均入场价 = 52.14%**。
* 所以"72.82% 赚钱"和"72.82% 方向正确"在这里数值恰好相同——但概念必须分开写，否则你换成均价 0.30 的入场就会看到"胜率 90%"却还在亏钱。

修正后，报告里现在同时给三个数：**方向命中率、盈亏平衡所需胜率、两者之差（edge）**。下表全部是这个口径。

## 二、核心结论：止盈在毁收益；止损要分两种口径看

839 笔交易、入场 T-120/T-60、`movePct=0.05`、真实手续费 `shares×0.07×p×(1−p)`、双边 50bps 冲击成本。

**先说一个重要前提（我核对过原始 CSV）**：下表每一列都是**单独一条规则的独立测试**，不是组合执行。
证据：`SL 净利`在所有 TP 取值下**完全相同**（9,762 / 10,304 / 13,992 … 一行一行对得上），说明两者没有交互计算。
**所以本回测无法回答"TP 和 SL 同时挂上会怎样"** —— 那需要逐笔按盘中价格先后顺序判定，请看第六节第 2 条。

### 止盈（固定 TP，其余持到结算）

| TP | 触发率 | 净利 | 结论 |
|---|---|---|---|
| 0.03 | 90.5% | **−2,017** | 亏钱 |
| 0.05 | 86.7% | 1,200 | 勉强打平 |
| **0.10（你的设置）** | 80.5% | **10,427** | 明显浪费 |
| 0.20 | 70.0% | 22,847 | |
| **0.30** | 61.7% | **34,515** | 最好 |
| — 不止盈，持到结算 | — | **28,597** | 次好 |

**单调递增，方向明确：止盈越紧，收益越差。** 你的 `tp=0.10` 把净利从 28,597（不止盈）压到 10,427，**让掉了 64% 的利润**。

原因是结构性的：这是**二元结算**市场，获胜方向的终值本来就是 **1.0**。你在 0.62 止盈，等于主动放弃 0.38；而触发率 80.5% 说明**绝大多数赢单都被提前掐断**。
TP=0.30 之所以比"不止盈"还好（34,515 > 28,597），是因为它把一部分"方向对但没走到 1.0"的单子锁在 0.30 以上。

### 组合执行（两个单子同时挂着，谁先碰到谁成交）—— 这才是实盘口径

上面那张表是**单规则独立测试**（原始 CSV 可证：`SL 净利`在所有 TP 取值下完全相同，说明没有交互）。
但实盘你是 TP 和 SL **同时挂着**，所以下面这张表才真正对应你的执行方式。它逐笔按盘中价格顺序判定，先碰到哪个算哪个（同一笔成交内并列时按 SL 计，保守）。

| TP | SL | 组合净利 | 组合胜率 | TP 触发 | SL 触发 | 最大回撤 | （对照）持到结算 |
|---|---|---|---|---|---|---|---|
| **0.10** | **0.05（你现在）** | **2,808** | 62.7% | 57.8% | 32.3% | 1,815 | 28,597 / DD 1,279 |
| 0.20 | 0.20 | 18,228 | 75.2% | 65.1% | 14.8% | 1,073 | 28,597 |
| **0.30** | **0.20** | **28,967** | 72.7% | 57.6% | 16.0% | **866** | 28,597 / DD 1,279 |
| 0.30 | 0.15 | 27,035 | 69.4% | 54.8% | 19.9% | 855 | 28,597 |
| 0.30 | 0.10 | 24,477 | 64.8% | 50.8% | 25.9% | 851 | 28,597 |
| 0.30 | 0.05 | 18,915 | 54.2% | 41.6% | 39.7% | 1,065 | 28,597 |
| 0.30 | 0.03 | 13,530 | 44.8% | 34.2% | 51.8% | 1,340 | 28,597 |

**三条结论（第二条纠正了我自己前面的判断）：**

1. **你现在的 `TP0.10 / SL0.05` 组合几乎是最差的一档：净利只有 2,808。**
   而不挂任何止盈止损、持到结算是 **28,597**。**你的止盈止损吃掉了 90% 的收益。** 这是本次优化最重要的一句话。
2. **止损太紧是在主动制造亏损。** `SL=0.03` 时 SL 触发率 51.8%、胜率跌到 44.8%、净利 13,530；`SL=0.20` 时触发率仅 16.0%、胜率 72.7%、净利 28,967。
   我前面基于"单规则表"写过"止损保持 0.05 不要动"——**在组合口径下这个建议是错的。** 组合执行时，紧止损会被盘中噪声扫掉，把本来会结算成 1.0 的单子提前砍在低位。**单规则测试会系统性低估紧止损的伤害。**
3. **最优组合：`TP=0.30 / SL=0.20` → 净利 28,967，最大回撤 866，是所有方案里最低的**（比持到结算的 1,279 还低 32%）。
   即：**更宽的止损不仅多赚，还更安全**。它避免的是"在噪声里割肉"这种纯损失。

顺带说明：单规则表里"止损越宽越好"（SL=0.20 净利 24,289）与组合表的结论一致，方向没错；**错的是我当时建议"保持 0.05 不动"**——因为单规则表里 0.05 看起来是个无害的折中，而组合表显示它是灾难性的。

## 三、胜率怎么提高：靠拉长观察窗口，不是靠晚进场

方向命中率随**观察窗口（lookback）**单调上升，这是本次最重要的可操作发现：

| 观察窗口 | T-120 入场 | T-60 入场 |
|---|---|---|
| 60 秒 | 62.70% | 59.13% |
| 120 秒 | 67.14% | 65.45% |
| **180 秒** | **73.13%** | **69.52%** |
| 300 秒 | 75.90% | 89.01% |

**你的 `windowMin=2`（120 秒）偏短。改成 3 分钟（180 秒）能把命中率从 67% 提到 73%。**

但必须说清楚它的本质：观察窗口越长，你读到的是**窗口早期的动量**，而不是"末秒结构"。
300 秒窗口在 15 分钟市场里等于"从开盘算起"——那已经不是末秒狙击，是**动量跟随**了。这个策略实际赚的钱来自动量，不是来自末秒。

### 还有一个硬约束：你的数据里根本没有 T-30 以下的成交

| 入场时点 | 可用交易数 |
|---|---|
| T-120 | 466 |
| T-60 | 373 |
| T-30 / T-15 / T-5 | **0** |

**"末秒狙击"在 T-30 以内无法回测，也无法验证。** 这些 15 分钟市场在最后 30 秒没有可成交的挂单/成交记录。
如果你的实盘打算在 T-5 下单，这段代码在你的数据上给不出任何证据——**要么换更细的数据（orderbooks 有 1.8 秒粒度快照），要么把入场时点定在 T-60 之前。**

## 四、模拟盘与实盘的差距（这是你最该警惕的部分）

我在回测里显式建模了四项实盘摩擦，结果如下：

| 项 | 理想成交 | 实盘现实成交（入场 +50bps、出场 −50bps） |
|---|---|---|
| 净利（TP0.10/SL0.05） | 10,427 | **9,498（−8.9%）** |
| 净利（持到结算） | 28,597 | **28,038（−2.0%）** |

**冲击成本本身吃掉 2~9%，不致命。真正致命的是下面四条，它们在我的回测里"看不见"，但在实盘里会吃掉你的账户：**

1. **入场价用的是"最后一笔成交价"，实测平均滞后 5.4 秒、p90 = 7.0 秒、最长 209 秒。**
   回测里我按这个价成交；实盘你挂单时的盘口可能已经走开。**而且这不是小事：**

   | 报价新鲜度 | 笔数 | 方向命中率 | 组合净利 |
   |---|---|---|---|
   | ≤ 10 秒 | 774 | **76.0%** | **+4,723** |
   | > 10 秒 | 65（7.7%） | **35.4%** | **−1,915** |

   **陈旧报价的方向命中率只有 35.4%——比抛硬币还差。** 逻辑很直白：当最后一笔成交是 30 秒甚至 3 分钟前，你读到的"现货已确认方向"其实是一个**作废的价格**，此时下单等于随机下注。
   这 65 笔吃掉了全部亏损，所以**实盘必须加 10 秒陈旧闸门**——比任何参数调优都值钱。
2. **盘口价差 0.80（中位）。** 成交价 ≠ 中间价，你只能吃对手价。回测用成交价是对的，但**你得先有对手盘**——99.77% 的快照价差 ≥ 0.50 说明这些市场深度极差。
3. **只有 548 / 1,901 个市场能在 T-120 配对出两侧价格。** 也就是**71% 的市场在关键时刻没有可交易报价**。实盘里你会大量遇到"信号来了但下不进去单"。
4. **盈亏平衡线是平均入场价 52.14%，而实际成交价分布很宽（0.02~0.98）。** 入场价高于 0.60 的交易，需要 60%+ 命中率才不亏；若滑点再吃掉 2 分，就变成 62%。**建议加一条硬闸门：入场价 > 0.65 直接放弃。**

### 建议的实盘保护措施（按优先级，全部基于实测数据）

| 优先级 | 措施 | 具体阈值 | 实测依据 |
|---|---|---|---|
| 🔴 P0 | **报价陈旧就不做** | 最后一笔成交距今 **> 10 秒** → 放弃 | 陈旧单（>10s，占 7.7%）方向命中率只有 **35.4%**、净利 **−1,915**；新鲜单（≤10s）命中 **76.0%**、净利 **+4,723**。**这 65 笔交易贡献了全部亏损。** 换成实盘口径就是：**你的信号基于一个已经作废的价格**，等于随机下注 |
| 🔴 P0 | **滑点上限** | 对手价偏离信号价 > 2 分（200bps）→ 不下单 | 薄盘被扫；报价陈旧本身就会伪装成"滑点" |
| 🔴 P0 | **止损放宽到 0.20** | 见第二节 | 组合净利 2,808 → 28,967，回撤同时降 52% |
| 🟠 P1 | **止盈放到 0.30** | 见第二节 | 同上 |
| 🟠 P1 | **成交后校验** | 实际成交价 vs 预估 VWAP 偏离 > 1.5 分 → 告警 | 识别异常成交/被针对 |
| 🟡 P2 | **仓位代替紧止损** | 单笔 ≤ 1% 权益 | SL 越紧净利越低（实测），风险应靠仓位而非割肉控制 |

**关于"入场价上限"——我最初的建议是错的。** 我原以为"入场价 > 0.65 需要 65%+ 胜率，风险高"，实测推翻了这个直觉：

| 分组 | 笔数 | 方向命中率 | 组合净利 |
|---|---|---|---|
| 入场价 ≤ 0.65 | 493 | **54.8%** | +1,445 |
| 入场价 > 0.65 | 346 | **98.6%** | +1,363 |

高价入场这组的命中率高达 **98.6%**——因为市场**已经把方向定死了**（价格接近 1.0 就等于结果已定）。虽然每笔只赚不多（+3.94/笔），但**它们是赚的，不是亏的**。
所以**不要加 0.65 的上限**；真正该卡的是**报价陈旧**。这也解释了为什么整体胜率看起来很高：一部分交易本来就是在买"已经确定的结果"。

## 五、最终参数建议

```jsonc
{
  "strategy": {
    "entry_t_minus": 120,        // T-120 为主（T-30 以内无成交数据，不可验证）
    "lookback_window_s": 180,    // ← 从 120 改到 180：命中率 67% → 73%
    "move_pct": 0.0015,          // ← 确认单位！0.15 若指 15% 则永不可能触发
    "take_profit": 0.30,         // ← 从 0.10 改到 0.30
    "stop_loss": 0.20,           // ← 从 0.05 放宽到 0.20（关键！见第二节）
    "min_entry_price": 0.08      // 不设上限：实测高价入场是赚的
  },
  "execution": {
    "max_quote_staleness_s": 10, // ← P0：陈旧报价直接放弃（实测唯一稳定亏钱的来源）
    "max_slippage_bps": 200      // ← 新增硬闸门
  },
  "risk": {
    "max_position_pct_equity": 1.0   // 用仓位控制风险，而不是紧止损
  }
}
```

**两处必改 + 一处必加：**
* `take_profit` 0.10 → **0.30**，`stop_loss` 0.05 → **0.20** → 组合净利 **2,808 → 28,967（约 10 倍）**，最大回撤 **1,815 → 866（−52%）**
* 新增 `max_quote_staleness_s = 10` → 剔除那 7.7% 的陈旧单（它们方向命中率仅 35.4%、净利 −1,915，是全部亏损来源）

**预期表现（必须带着这些前提读）**：方向命中率 ~73%，盈亏平衡需 52.14%，**edge ≈ +21 个百分点**，839 笔样本、100 USDC/笔下净利 +28.9k。

## 六、这个结论有多可信（必读的自我质疑）

我主动列出会削弱上述结论的因素，请你据此决定投入多少真金白银：

1. **只有 1 天数据。** 839 笔交易、单个文件。BTC/ETH/SOL/XRP 四种资产混在一起，没有分资产验证。
2. **TP 与 SL 的交互已测，但顺序假设保守。** 组合口径下我按"逐笔价格顺序、先碰到先成交、同笔内并列算 SL"处理。这比独立规则真实得多，但仍假设你能在触发价成交——**薄盘里这正是做不到的地方**（回测给的 16~32% 的 SL 触发率，实盘可能因为滑点更高）。
3. **命中率随 lookback 单调上升是危险信号**：它说明收益主要来自"早期动量延续"，而动量效应在样本外（尤其行情结构变化时）最容易衰减。**建议做时序切分验证：用前 60% 时间调参、后 40% 验证。**
4. **入场价来自交易记录而非盘口**，等于假设你的限价单一定成交在别人成交的价位——实盘只有吃单能保证。
5. **未计入资金费率/机会成本/链上 gas**。

**我的建议**：先按第五节参数做**纸上跟踪 2 周**，重点记录三件事——(a) 信号触发但下不进去单的比例；(b) 实际成交价与信号价的偏离分布；(c) 入场价 > 0.60 的那部分单独统计胜率。这三项数据拿到后，再决定是否上真金。
